Retrieval-Augmented Generation (RAG) is a technique that enhances large language models by retrieving relevant information from external knowledge sources before generating a response. This approach addresses key limitations of standalone LLMs, such as stale training data, hallucination, and lack of domain-specific knowledge.

The core RAG workflow consists of two main phases: indexing and retrieval-generation. During indexing, documents are split into smaller chunks, each chunk is converted into a vector embedding using an embedding model, and these vectors are stored in a vector database. During retrieval-generation, a user query is embedded using the same model, the vector database is searched for the most similar chunks, and those chunks are provided as context to an LLM to generate a grounded answer.

There are several critical design decisions when building a RAG system. Chunking strategy determines how documents are split: fixed-size chunks are simple but may break semantic boundaries, while semantic chunking uses natural boundaries like paragraphs or sentences. The choice of embedding model affects retrieval quality — smaller models like all-MiniLM-L6-v2 (384 dimensions) are fast and lightweight, while larger models like text-embedding-3-large (3072 dimensions) offer higher accuracy at the cost of speed and memory.

The vector database stores embeddings and enables efficient similarity search. Options range from in-memory solutions like FAISS for prototyping, to lightweight embedded databases like Zvec, to production-grade systems like Qdrant, Pinecone, or Weaviate. The key operations are insert (adding new vectors) and query (finding nearest neighbors by cosine similarity or Euclidean distance).

Retrieval quality can be improved through several techniques. Hybrid search combines dense vector search with sparse keyword search (BM25) to capture both semantic and exact-match signals. Re-ranking applies a cross-encoder model to reorder the top-k results for better precision. Query rewriting expands or reformulates the user's question before retrieval to improve matching.

Prompt engineering is crucial for RAG quality. The prompt should clearly separate context from the question, instruct the model to answer only from provided context, and specify how to handle insufficient information. A basic template might include sections for system instructions, retrieved context with source citations, and the user's question.

Evaluation of RAG systems typically measures retrieval metrics (hit rate, Mean Reciprocal Rank, Mean Average Precision) and generation metrics (answer relevance, faithfulness, completeness). Tools like RAGAS provide automated evaluation frameworks that score these dimensions without requiring human annotation.

Common failure modes in RAG include: the embedding model failing to capture the semantic meaning of specialized terms, chunks being too large (containing irrelevant information) or too small (missing necessary context), the retriever missing relevant chunks due to vocabulary mismatch, and the LLM ignoring or contradicting the provided context. Each of these failure modes has specific mitigation strategies.
